# VideoStudio

Веб-приложение для предоставления услуг видеосъёмки. Проект представляет собой REST API, обеспечивающий управление услугами, портфолио, расписанием, бронированиями, отзывами и пользователями.

## Технологический стек

- **C#**
- **.NET 9 / ASP.NET Core Web API**
- **Entity Framework Core 9**
- **SQLite** — база данных
- **ASP.NET Core Identity** — управление пользователями и ролями
- **JWT (JSON Web Token)** — аутентификация и авторизация
- **Swagger / OpenAPI** — документация и тестирование API
- **IMemoryCache** — кеширование данных

## Описание основных файлов

### Controllers

Контроллеры обрабатывают HTTP-запросы и обеспечивают взаимодействие клиента с серверной частью приложения.

| Файл | Назначение |
|---|---|
| AccountController.cs | Регистрация пользователей, вход, выход и генерация JWT-токенов. |
| BookingsController.cs | Создание бронирований, просмотр записей, изменение статусов и отмена бронирований. |
| ContactController.cs | Приём сообщений из контактной формы, просмотр и управление сообщениями. |
| NotificationsController.cs | Получение уведомлений текущего пользователя и отметка уведомлений как прочитанных. |
| PortfolioController.cs | Получение списка работ, просмотр отдельных записей, добавление, редактирование и удаление элементов портфолио. |
| ProfileController.cs | Получение информации о профиле и проверка доступа к функциям администратора и менеджера. |
| ProfileManagementController.cs | Изменение личных данных пользователя и смена пароля. |
| ReviewsController.cs | Получение отзывов, добавление новых отзывов, их модерация и удаление. |
| ScheduleController.cs | Создание временных слотов, просмотр расписания, изменение доступности и удаление слотов. |
| ServicesController.cs | Получение списка услуг, просмотр отдельной услуги, добавление, редактирование и удаление услуг. |
| UsersController.cs | Просмотр пользователей, изменение их ролей и удаление пользователей. |

### Data

**ApplicationDbContext.cs**

Контекст базы данных Entity Framework Core.

Наследуется от `IdentityDbContext<ApplicationUser>` и обеспечивает работу с таблицами:

- Пользователи и роли Identity.
- Services.
- PortfolioItems.
- Bookings.
- Reviews.
- ContactMessages.
- Schedules.
- Notifications.

### Models

Модели описывают сущности приложения и структуру хранимых данных.

| Файл | Назначение |
|---|---|
| ApplicationUser.cs | Расширенная модель пользователя Identity с дополнительным полем FullName. |
| Booking.cs | Бронирование услуги: пользователь, услуга, временной слот, дата, комментарий и статус. |
| ContactMessage.cs | Сообщение, отправленное через контактную форму. |
| Notification.cs | Уведомление пользователя с заголовком, текстом, датой создания и статусом прочтения. |
| PortfolioItem.cs | Элемент портфолио с названием, описанием, изображением и видеоматериалом. |
| Review.cs | Отзыв пользователя с оценкой, текстом и статусом модерации. |
| Schedule.cs | Временной слот расписания с началом, окончанием и признаком доступности. |
| Service.cs | Услуга с названием, описанием, стоимостью, изображением и признаком активности. |

| ReviewDto.cs | Данные для создания отзыва. |
| ScheduleDto.cs | Данные для создания временного слота. |
| ScheduleUpdateDto.cs | Данные для изменения доступности временного слота. |

### Migrations

Содержит миграции Entity Framework Core, которые позволяют создавать и изменять структуру базы данных.

Известные миграции проекта:

- `InitialCreate` — начальная структура базы данных.
- `AddSiteModels` — добавление основных моделей сайта.
- `AddSchedule` — добавление расписания.
- `AddScheduleTimeSlots` — переход к системе временных слотов и связи бронирований с расписанием.
- `AddNotifications` — добавление системы уведомлений.

### Корневые файлы

**Program.cs**

Основной файл запуска приложения.

Выполняет:
- Регистрацию сервисов ASP.NET Core.
- Настройку Entity Framework Core и SQLite.
- Настройку ASP.NET Core Identity.
- Настройку JWT-аутентификации.
- Регистрацию кеширования.
- Настройку Swagger с поддержкой Bearer-токенов.
- Автоматическое создание ролей Admin, Manager и User.
- Создание начального администратора.
- Настройку middleware и маршрутизации контроллеров.

**appsettings.json**

Файл конфигурации приложения.

Содержит:
- Строку подключения к SQLite.
- Настройки журналирования.
- Параметры JWT: ключ, издатель, аудиторию и время действия токена.

Файл проекта .NET.

Содержит целевую версию платформы, настройки компиляции и список NuGet-зависимостей.

**Properties/launchSettings.json**

Настройки локального запуска приложения, включая профили запуска и адреса разработки.

## Реализованный функционал

### 1. Регистрация и авторизация

- Регистрация новых пользователей.
- Вход по email и паролю.
- Хеширование паролей средствами ASP.NET Core Identity.
- Генерация JWT-токенов.
- Проверка JWT при обращении к защищённым маршрутам.
- Поддержка ролей Admin, Manager и User.

### 2. Управление услугами

- Получение списка активных услуг.
- Получение информации об отдельной услуге.
- Добавление новых услуг.
- Редактирование существующих услуг.
- Удаление услуг посредством деактивации.
- Кеширование списка услуг на 5 минут.

### 3. Портфолио

- Просмотр списка работ.
- Получение отдельной работы.
- Добавление элементов портфолио.
- Редактирование и удаление работ.
- Кеширование списка портфолио на 5 минут.

### 4. Расписание и бронирование

- Создание временных слотов.
- Проверка корректности временных интервалов.
- Проверка пересечения слотов.
- Получение доступного расписания.
- Создание бронирования пользователем.
- Проверка доступности услуги и временного слота.
- Резервирование временного слота при создании записи.
- Просмотр собственных бронирований.
- Управление статусами записей.
- Отмена бронирования пользователем.
- Освобождение временного слота после отмены или отклонения записи.

Поддерживаемые статусы бронирования:

- Pending — ожидает подтверждения.
- Confirmed — подтверждено.
- Rejected — отклонено.
- Cancelled — отменено.

### 5. Отзывы

- Добавление отзывов авторизованными пользователями.
- Проверка оценки от 1 до 5.
- Публикация только одобренных отзывов.
- Модерация отзывов администраторами и менеджерами.
- Удаление отзывов.

### 6. Контактная форма

- Отправка сообщений посетителями.
- Проверка имени, email и текста сообщения.
- Просмотр сообщений сотрудниками.
- Изменение статуса прочтения.
- Удаление сообщений администратором.

### 7. Личный кабинет

- Просмотр профиля.
- Изменение имени и номера телефона.
- Смена пароля с проверкой текущего пароля.

### 8. Управление пользователями

- Просмотр списка пользователей.
- Изменение ролей.
- Удаление пользователей.
- Ограничение административных операций по ролям.

### 9. Уведомления

- Создание уведомления при бронировании.
- Уведомление пользователя об изменении статуса записи.
- Уведомление сотрудников об отмене бронирования пользователем.
- Просмотр уведомлений.
- Отметка уведомлений как прочитанных.

Уведомления реализованы внутри приложения. Интеграция с электронной почтой и SMS не реализована.

## Безопасность

В проекте используются:

- ASP.NET Core Identity для управления учётными записями.
- JWT для проверки подлинности запросов.
- Ролевая авторизация.
- Проверка владельца бронирования и уведомления.
- Валидация входных данных с помощью Data Annotations.
- Проверка доступности временных слотов при бронировании.
- Защита административных маршрутов атрибутами `[Authorize]`.

```bash
git clone <repository-url>

```

```bash
dotnet restore
```

```bash
dotnet ef database update
```

```bash

```

После запуска Swagger доступен по адресу, указанному в профиле запуска приложения.

В режиме разработки документация API доступна через Swagger UI.

## Проверка работоспособности

Для тестирования API можно использовать Swagger UI.

В Swagger доступны операции регистрации, авторизации, работы с услугами, расписанием, бронированиями, отзывами, сообщениями и уведомлениями.

Для проверки защищённых маршрутов необходимо:

1. Зарегистрировать пользователя или использовать существующую учётную запись.
2. Выполнить вход через `/api/Account/login`.
3. Скопировать полученный JWT-токен.
4. Нажать Authorize в Swagger.
5. Ввести токен в поле Bearer.
6. Выполнить запросы к защищённым маршрутам.

## Текущий статус проекта

Серверная часть проекта реализует основные операции управления пользователями, услугами, портфолио, расписанием, бронированиями, отзывами, контактными сообщениями и уведомлениями.

На текущем этапе основной backend-функционал реализован.

Frontend-интерфейс, включающий публичные страницы сайта, личный кабинет и административную панель, должен быть разработан и подключён к API отдельно.
